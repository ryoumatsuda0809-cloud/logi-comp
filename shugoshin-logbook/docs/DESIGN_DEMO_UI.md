# デモ画面 UI の調査と設計（2026-11-24）

土台は `docs/DESIGN_SCHEME.md`（案A：明るいガラス）。この文書は、その「まだ」の部分（発注・報告書・警告）と、`/demo` に残る点を、実画面を見て洗い出したもの。

## 目的と見る人
- ポートフォリオとして企業（採用担当）に見せる。ログイン不要・架空データで、その場で触れる。
- 本体アプリではなくデモを見せる理由: 本体はログイン・実GPS（施設500m以内）・DBが要り、見る人がその場で操作できない。デモは本体と同じ計算ロジックを使っている。
- **PCで開かれる前提も置く**（これまでの確認は iPhone 中心）。

## 調べ方
- `main`（d2fad5b, 2026-11-11）を dev サーバーで開き、4画面を 375px と 1280px で撮影。
- 観点: 最初の数秒で伝わるか／画面をまたいで揃っているか／押す場所が見えるか／読みやすさ。
- Mobbin（UI事例の検索）は有料プランが必要で使っていない。

## 進め方（1画面ずつ・小さいPR）
1. **共通**: 注意書きの帯と、上の題名の行（帯の代わり）を部品にする（H1〜H3）。`PageHeader` は本物の画面でも使うので、デモ側だけ差し替える。
2. **発注**: タブ・注意書き・例文・ボタン（H4, M4）。
3. **報告書**: ボタンの形・スマホの要点カード・「御中」（M1〜M3）。
4. **警告**: ボタンの形・左寄せ（M1, 低）。
5. **`/demo`**: 再生・打刻の位置（H5）、折り返し（M5）。
6. 文字の色の実測と直し（M6）。

各段で守ること（`DESIGN_SCHEME.md` から）: 色は増やさない／橙は1画面に1つ／配管と印刷の紙面は触らない／押す場所は44px以上・文字12px以上。

## 追記（2026-11-25）：文字の量のルール

本人の感覚「文字が多い」を実際に数えて確かめた。/demo の待機料タブは最初の表示で説明文が5文・169字、発注の解析後は最大約230字あり、同じ数字（¥3,350・152分・3施設）が1画面に3〜4回、「500m」は4回、「書き換えられない」は3回出ていた。

### 基準にした調査結果
- 人は画面の文字の約2割しか読まず、F字に拾い読みする。スマホでも同じ（NN/g）。
- Apple の WWDC25「小さな書き換えで大きな効果」：同じことを2回言わない／飾りの言葉を消す／見出しは短く、理由は本文か別の所に置く／1つの操作に1つの言葉。
- Apple の UXライティングチーム：その情報がその瞬間に必要かを問い、少しずつ出す（段階的に開示）。
- ネイティブの定番の形：大きな数字＋短いラベル＋単位。状態は色と1語のバッジ。説明は押したら出るシートに置く。

### ルール（4画面共通）
1. 最初の表示で見える説明文は、1画面（1タブ）に1文まで。
2. 同じ数字・同じ意味は、1画面に1回だけ。
3. 見れば分かる操作は説明しない。
4. 守りの注意書き（架空のデータ、外部AIへの送信、法的助言ではない旨）は短くして残す。
5. 紙面（報告書・発注書・警告レポートの書面とPDF）の文は触らない。
